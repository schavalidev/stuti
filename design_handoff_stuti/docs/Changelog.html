0.9.90
4 September 2026
The prototype, ported — and a first Android build in hand.

Off the seventy-seven script tags, into a real build — and onto a phone

Added

The Vite + TypeScript port (stuti-app/)

Every plain .js and .jsx file became an ES module, in the exact load order Stuti.html always used, with window.X globals replaced by real imports — the phase the handoff called the port's foundation. Written as a small pipeline of scripts rather than by hand, because the alternative was retyping 1.7 MB of Sanskrit, Telugu and Hindi text and trusting nothing got mistranscribed along the way; the scripts live in tools/codemod/ and rerun cleanly if the prototype's source ever moves again. stuti-boot.js and the CDN copies of React and Babel it fetched at runtime are gone — Vite compiles JSX at build time now, which is one less thing that can fail without wifi in the pūjā room.

Fixed

Three bugs the port surfaced that predate it

The shared-script-scope the prototype relied on hid a few things a real module graph can't: PracticeView read a lens variable that was never in its scope, which would throw the moment anyone opened a practice's detail screen — dead code until now, not dead by design. FlowText's memoised wrapper was being discarded in favour of the unmemoised function on export, quietly costing the re-renders the memo existed to avoid. And stuti-remind.jsx's public fmtNudgeTime name pointed at nothing, its local function having been exported under a rename the old global scope papered over. All three are what they were designed to be again.

Added

Android, via Capacitor — first signed build

A dedicated release keystore, a Capacitor shell around the Vite build, and a from-scratch command-line Android toolchain (no Android Studio) — JDK 21, the SDK's own cmdline-tools, nothing else. vite-plugin-pwa replaces the hand-written stuti-sw.js with the same intent: precache the app shell, cache-first for fonts and emblems, so a closed tab and a closed pūjā-room door mean the same thing to the app either way. Onboarding, the home pañcāṅga card, the saṅkalpa sheet, library and reader all checked against a live dev server and render correctly — the parity baseline the handoff asked for.

Added

One repo for both halves — github.com/schavalidev/stuti

The designer keeps exporting from Claude Design and the port has to keep up, so the two now live side by side on main: design_handoff_stuti/ exactly as exported (a future export drops straight in), stuti-app/ generated from it. That only works if regenerating is safe, and it wasn't — a rerun of the pipeline had already erased the entry point once and would have taken every later hand-fix with it. So the pipeline now owns the whole result: the entry files come from templates, every after-the-fact fix is a scripted step that fails loud on an unexpected anchor, the load order is read from the prototype's own Stuti.html rather than copied out of it, and a removed source file removes its module. tools/codemod/.ported-at records which design commit src/ came from; tools/check-design-updates.sh compares that against the remote and lists what the designer has pushed since. Signing keys and their passwords are ignored by name and were checked to be, before the first commit.

Added

The web build, live — stuti-app.netlify.app

The installable half of "both": the same Vite build, served over HTTPS so the service worker and the manifest do their work and Android Chrome offers Add to Home Screen. netlify.toml at the repo root drives it, so a site linked to the GitHub repo redeploys on every push as well. The first deploy built cleanly and then failed looking for Stuti/dist: with the config at the root, publish resolves against the root even when base is set — it has to name stuti-app/dist outright. The service worker is served with no-cache so a deploy can reach devices that already hold the previous one. One more thing the first deploy exposed: the manifest pointed at the 320×96 wordmark declared as a 512-pixel icon, and Android Chrome checks the real dimensions before it offers Add to Home Screen. The icon is now the kalasha — the brand mark the home page already preloads — in the manifest sizes plus a maskable variant inset on cream so the circular crop keeps the leaves, and the same source feeds every Android launcher density and the splash, replacing Capacitor's placeholder.

Next

What this build still doesn't do

Sign-in, sync, dāna and reminders behave exactly as the prototype's own tracker already describes them — local-only, honestly so. Real accounts and cross-device sync are the next milestone, once a Supabase project exists to point them at, and they go in new modules that wrap the generated stores, never in the generated files themselves. A scheduled check that runs check-design-updates.sh and reports what the designer has pushed is the remaining piece of the collaborative setup.

The gap between an artefact and a product, written down.

A launch tracker, because the prototype had started to look finished

Added

Launch Tracker — what is real, what only looks real

The launch plan covers the fortnight to the beta; nothing covered the longer road behind it, and the app had reached the point where a screen that works on the builder's phone reads as shipped. The tracker states the three conditions plainly — real, prototype, missing — and puts every substantial capability into one of them, with the promise each prototype makes on the app's behalf: the stub session that mints an id and authenticates nobody, a year of practice living in one browser's local storage with no export, a giving screen whose Razorpay slots are blank, a print meter that both contradicts the app's own stance and resets with a cleared cache, and reminders that ring only while a tab is open. Above that, a five-stage ladder from prototype to sustaining, so stage-four costs stop being paid during stage two.

Added

The corpus's shape decided by what hymn text actually is

The storage question was asked as a database question and it isn't one. Measured rather than guessed: 1.7 MB of hymn text across forty files, all of it loaded into memory on every page open behind seventy-seven script tags, at roughly seventy of the hundred and twenty-seven catalogued titles — three megabytes at the full index, eight to ten at three hundred texts. Hymn text is immutable, identical for everyone, and wanted one document at a time, which is file-shaped and not database-shaped: one JSON document per stotra on a CDN, fetched on demand, cached per hymn by the service worker, with a slim index carrying the library and search. The small mutable remainder — accounts, lists, the ledger, gifts, push subscriptions — is what earns a database. Audio inherits the same logic with a bandwidth bill instead of a storage one.

Added

The decisions no amount of code will settle

Eight open questions inside the product, each with a recommendation attached, because an undecided question quietly blocks work in three other places: whether a paid tier exists at all, how narrow the launch corpus is, and — the deepest one in the product — who has the authority to say a text is correct. Eleven outside it, several with lead times measured in weeks rather than hours: the entity that has to exist before a rupee can move, the trademark and the domain, a rights basis recorded for every text, the privacy duties that arrive with the first real account, and the two questions worth answering before they answer themselves — what happens if it works, and what happens if the builder stops.

Added

A first-time founder's guide — twenty-eight days, each with a "done when"

The tracker says what must become real; nothing said what to do on Tuesday. The guide lays out 7 September to 4 October one day at a time, in plain English, each day carrying what to do, why it matters, and the single observable fact that proves it finished — because a first-time founder's most expensive habit is ticking a day when they feel done rather than when it is. The month runs two tracks on purpose: the app, and the slow world around it — the accountant, the entity, the domain, the reviewers, the policies — scheduled first because a reply that takes weeks has to be asked for in week one. The ops checkmark script now recognises any row carrying a work id, not only the original checklist rows, so the day cards and week counters persist like everything else.

Added

The daily plan — the same month in plainer words

The four-week guide explains itself well but reads dense when the question is only "what do I do this morning?" — the "why" and the "do" sit at the same weight. The daily plan is the same twenty-eight days with the priority pulled out: one main job per day in a gold block, the smaller jobs under it marked as optional, a "done when" in one sentence, and a standing list of what you will be waiting on. Ticks are shared with the guide, so either page can be the one you open. Short words throughout; the guide keeps the reasoning.

Fixed

The operations documents could not scroll

The app stylesheet pinned the document to the viewport for every page that borrowed its tokens — right for a phone shell whose panes scroll themselves, wrong for the plan, the tracker, the glyph sheet, the audits and every other long page, all of which rendered their first screen and stopped there. The lock is now scoped to pages that actually contain the app shell; everything else scrolls as a document should.

Both bars take the reciter's order.

The lens bars can be arranged

Added

Long-press a pill, drag it where it belongs

Nitya's six lenses, and the library's seven, sat in the order we decided was sensible — recitation first, the ledger last — and that order is wrong for anyone whose day starts on the mālā or who keeps a nomu every month. Six pills do not fit a phone's width, so our sequence quietly taxed theirs: a scroll and a reach, every morning, for the lens they actually live in. A long press on any pill now puts the bar into arranging: the unchosen pills go to a dashed outline, a line appears beneath the bar carrying the instruction and the way out, and a pill follows the finger into any position. Order is saved as it moves, so leaving the mode is only leaving the mode. Done sits in that line rather than at the end of the pill row — the row scrolls, and an exit that scrolls off the right edge is no exit at all on a phone, the more so because the pills stop answering taps while arranging. A press anywhere off the bar leaves the mode too.

The stored order is a list of ids reconciled against the real lens list on every read, not a frozen snapshot — a lens added later appears at its canonical place instead of vanishing, and one withdrawn drops out without leaving a hole. The gesture, its wording and its two saved orders live in one place, called by both bars — as the side-swipe already is. The drag itself is read on the window rather than on the pill: bound to the pill it died on the library bar, where a pill carrying an image — the kalaśa, the pārāyaṇa glyph — hands mousedown to the browser's own image drag, and where the row re-ordering under the finger leaves the element the press began on no longer beneath it. Reset appears only once the order actually differs from the one it shipped in, and it is held rather than tapped: undoing an arrangement someone built by hand should ask for the same deliberate gesture that built it, so the word reads "Hold to reset" while the finger is down and a released tap does nothing. While arranging, the side-swipe stands down, since a drag and a swipe are the same gesture read two ways and the pill under the finger has the better claim; a tap no longer switches lens, and Escape leaves the mode from a keyboard.

The lens bars can be swiped through

Added

A side-swipe moves to the next lens

Seven lenses do not fit a phone's width, so reaching pārāyaṇa meant scrolling the bar sideways and then hitting a pill — two gestures for what is one thought. A horizontal swipe anywhere on the library now steps through the row in its own order: deity, type, māsa, vrata, festival, nomu, pārāyaṇa. The ends do not wrap; there is nothing past pārāyaṇa, and the swipe simply does nothing rather than throwing the reciter back to the start. Nitya answers the same gesture across its own six — pāṭha, sādhana, japa, learning, nomu, the ledger — because it is the same instrument: one screen re-sliced by a row of pills too wide to see at once. The gesture lives in one place now and both bars call it.

It answers a mouse drag as well as a finger, and it is read on the window in the capture phase rather than on the library element. Bound to the element the swipe failed in two ordinary ways: a drag released outside it — over the tab bar, past the edge — never delivered its end event, and any child that swallowed the event ate the swipe silently, which is why a vrata row felt dead while blank space worked. Captured at the top, the whole screen answers; only the strips that own the horizontal axis themselves, the lens bar and any chip rail wider than its frame, opt out. Travel of 45px counts, and the horizontal move must beat the vertical.

A trackpad side-swipe is not a pointer gesture at all — it arrives as wheel deltas — which is why a synthetic drag passed every test while the real gesture on a laptop did nothing. Deltas now accumulate until they clear the same travel, and one gesture may step exactly once. What separates two gestures is a quiet gap read from the events' own timestamps, not from the clock at the moment they are handled: on an expensive lens the flick's remaining momentum queues behind the render and is dealt with hundreds of milliseconds late, which every clock-based test — first a cooldown counted from the step, then a gap counted from arrival — mistook for a fresh swipe and stepped again, walking three lenses on one flick. An event's timestamp is set when the gesture produced it, so a slow render cannot forge a pause that never happened.

The bar follows the swipe. Changing the lens by gesture never touched the row, so the active pill could sit off-screen behind it and the reciter would meet a new screen with no visible sign of which lens produced it. The track now scrolls to centre the active pill, clamped at both ends so the first and last pills sit flush rather than half-scrolled into empty space.

One guard remains beyond that: a swipe is ignored while a detail view is open — inside a vrata or a nomu the sideways gesture belongs to that page and its own back arrow, not to the lens behind it. Nomu, which is hidden in Devanāgarī, is skipped in both sequences, so the swipe never lands on a lens the reciter cannot see.

Changed

A saṅkrānti is not a tithi. It is the instant the sun crosses from one rāśi into the next, and the calendar knew those instants to the minute while showing none of them. Makara Saṅkrānti — the one festival in the year fixed to the sun — was missing from an almanac that computes Uttarāyaṇa from it.

Six now stand in the observance list beside the lunar ones: Makara and Karka where the sun turns, Meṣa and Tulā where day and night level, Kanyā for Viśvakarmā, and Dhanu, which opens the thirty mornings of Dhanurmāsa and closes at Makara. Each carries its vidhi, its naivedya and what is given away, as the vratas do.

The day a transit is kept on is the transit's own, unless it falls after sunset — then the bathing and the giving move to the next morning. That is the whole reason Makara Saṅkrānti is the fourteenth of January in some years and the fifteenth in others: 2025 and 2026 the fourteenth, 2024 and 2027 the fifteenth. The ayanāṁśa setting moves these too, by three hours or so, which is occasionally a day — the first place that choice has ever been visible.

Fixed

Vākya was keeping drik's sunrise

Choosing vākya bought siddhāntic tithis read at a modern sunrise — a hybrid no printed almanac produces, and the one honest gap left in that feature. The siddhānta does not hunt the horizon: it takes the declination on an obliquity of exactly 24°, forms the earth-sine and the day-radius, and reads the cara off the same twenty-four-entry Rsine table the longitudes come from. Fifteen ghaṭikās plus the cara is the half-day.

What that yields is the geometric centre of the sun on a level horizon — no refraction, no semidiameter — so vākya sunrise now falls a minute or so after the drik one and sunset four or five minutes before it, a day about six minutes shorter. Local noon is solved rather than corrected, so the siddhānta's own bhujāntara and udayāntara fall out of it instead of being bolted on. Elevation still counts in both: the horizon really does drop away, whatever the scheme.

A real ephemeris under all five limbs

The pañcāṅga used to compute two limbs and illustrate three. It now computes all five from the apparent longitudes of the sun and the moon — Meeus for the sun, an abridged ELP for the moon — read at the day's own sunrise, which is the rule a printed pañcāṅga keeps.

Changed

One sun for the whole app

Naming the lunar month, deciding whether it is intercalary, and choosing the ṛtu are all decided by which side of a saṅkrānti the sun stands on. That call was being made by a second, private solar series with a straight-line ayanāṁśa — a tenth of a degree adrift, which at a saṅkrānti is not a tenth of a degree but a whole month. Every module now reads the same longitude, and it honours the ayanāṁśa you chose.

Changed

Sunrise, from the sun rather than from a curve

Sunrise and sunset were a fitted day-of-year formula, good to a minute or two. Every limb of the day is read at sunrise, so those two minutes were two minutes of error in all five. They are now the apparent sun's declination bisected onto the horizon, with the usual −0.833° for refraction and the sun's own width — the upper limb touching the horizon, which is what an almanac means. The old formula stays as a fallback, and polar days and nights are named instead of left blank.

Added

When a limb began, not only when it ends

A printed pañcāṅga gives both ends of every tithi, nakṣatra, yoga and karaṇa; the app gave only the hour each lets go. Most limbs take hold before midnight and only the ending is worth printing — but the ones that begin during the day now show both, which is the half a saṅkalpa actually names.

Moonrise, and the windows of the day

Moonrise is not decoration: a nakta vrata is broken on sighting the moon, and Saṅkaṣṭī is kept to it. It needed the moon's latitude as well as its longitude — the moon wanders five degrees off the ecliptic, worth the better part of an hour at the horizon.

With an exact sunrise and an exact nakṣatra, the rest of the day's windows follow: Rāhu kāla, Yamagaṇḍa and Gulika from the eightfold division, Abhijit as the eighth of fifteen and not kept on Wednesday, Brahma muhūrta before dawn, and Varjyam — which is a span inside a nakṣatra, at a fixed fraction of that nakṣatra's own length, and so could not be computed at all until the ephemeris landed.

  • Eleven time ranges in a list is a wall of numbers, and the question is “is this a good moment?” — so the day is one band from midnight to midnight, daylight tinted, with a line for now. Overlapping windows take their own lane; a thin span still gets a full-sized target.
