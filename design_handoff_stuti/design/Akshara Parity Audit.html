The parity audit

Stuti is the phone app; Akshara is the website. They have shared one almanac since 0.8 and one day-sheet since 0.9.0, and it is tempting to call that parity. It is not: everything the app does about practice — counting, keeping, planning, being reminded — stops at the phone. This audit sets each Stuti feature beside the website's answer to it, so the crossing can be planned rather than discovered.

What crossed in 0.8 and 0.9.0

The precedent for everything below: the engine is loaded as-is, and the screen is re-said in the site's own voice. Nothing here needs touching.

  • The ephemeris and all five limbs, with both ends of each
  • Seven kāla windows, moonrise and moonset, the running window
  • The saṅkalpa with its deśa clause, gotra and the sixty-year cycle
  • 200 places, searchable, with detect-my-location
  • The four reckoning preferences, on shared keys — one reciter, one set of habits
  • The six saṅkrānti solar days, computed not pinned
  • Festival and vratham guides with samāgri lists
  • Reading in six scripts, with parallel layout
  • Daily recitation list — playlist, mālā and night styles, drag to re-thread
  • Bookmarks, mock recitation with speed, transpile caching via StutiBoot

Group A — the practice layer

The largest gap: the site has a library, not a practice

All of Stuti's Nitya tab. The stores are plain modules — stuti-store.js, stuti-sadhana.js — so a household that counts on the phone should find the same counts on the site.

Missing

Daily threads and the sādhana streak

Per-hymn practice log: the unbroken thread, last sitting, lapses named by name rather than shown as a broken chain. The reckoning lives in stuti-sadhana.js; the site's daily list would gain a count and a thread under each entry.

Two shelves the site does not have

The data files are shared verbatim — stuti-nomu-data.js, stuti-parayana-data.js — and the guides reuse the vratham guide's own layout, so this group is mostly saying it in the site's type.

Pārāyaṇa — reading undertakings

Eight schedules — Sundarakāṇḍa, Devī Māhātmyam, the Gītā, the saptāha — each a schedule rather than a text: day-divisions the tradition allows, when it is begun, the niyama that holds it.

Missing

The full index, and the waiting list

Stuti's library merges stotra-index-data.js — hundreds of stotras by name, per deity, while their texts are keyed and proofed — and the site never loads it, so its shelves show only the keyed few. With the index comes the waiting state: rather than a dead end, ask to be told when a text arrives (stuti-watch.js, stuti-await.jsx).

Deliberately not crossing

What stays on the phone

The four-tab bottom bar and its lineage routing — the site has a top nav and a footer, and the phone preview already frames the site when a phone is wanted. The day-and-night sky as a full-bleed backdrop may shrink to a band. Kids mode is its own app and its own audit. Everything else in Stuti is, on inspection, portable.

A suggested order

Five crossings

1

The practice layer

Threads and streaks, japa, plans, vows, the record, the sandhyā guide. This is the actual ask — the rest decorates it. Load the stores first so phone and site count as one.

2

The two lenses and the waiting list

Nomulu, pārāyaṇa, watch-this-stotra, and every guide's foot pointing at its deity. Cheapest group; data crosses verbatim.

3

Reader depth

Padārtha, learn modes, the flyleaf, recording, sharing and printing, the name glossaries, and the search pool widened to the whole corpus.

4

The living Today

Sky, seasons, the sandhyā card, the greeting, the owed-list. The one phase with real design work — the sky must be composed for a wide screen, not stretched.

5

Reminders, preparation, and the system

Cues and quiet hours, the three-day prep nudge, onboarding, offline, the interface in three languages, night. Web push last — it is the only item needing anything beyond the browser.

Method note: statuses were read from the running code of both apps, not from memory — the site's router, its search pool, its theme table, and the phone's module list. Where the site half-has a thing, it is marked Partial and the missing half named. Effort is S, M, L for a working session, a day, and more than a day, in this codebase's terms.
